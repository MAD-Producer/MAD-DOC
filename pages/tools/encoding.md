# 编码、转码与交付

本页采用 VCB-Studio 教程所强调的基本流程：**识别源文件 → 仅处理已确认的问题 → 编码 → 封装 → 检查**。具体参数取决于素材、播放环境和平台规范，不设脱离场景的“万能参数”。

::: info 适用范围
VCB-Studio 教程主要面向动画压制与 BDRip。本页依据其中的视频基础、瑕疵识别和编码原则，转写为适用于 MAD·AMV 剪辑、合成和交付的工作规范；不复制其章节正文。
:::

## 一、先识别源文件

处理前应同时使用 MediaInfo、`ffprobe` 和画面观察记录以下信息：

| 项目 | 需要确认的内容 | 常见风险 |
| --- | --- | --- |
| 容器 | MKV、MP4、MOV、MXF 等 | 容器不受剪辑软件支持，不等于视频损坏 |
| 视频编码 | H.264、HEVC、AV1、ProRes、DNxHR 等 | 高压缩长 GOP 编码解码负担较高 |
| 像素格式 | 4:4:4、4:2:2、4:2:0 | 色度采样不足时，文字、线条和抠像边缘更易受损 |
| 位深 | 8-bit、10-bit、12-bit | 低位深渐变更容易出现色带 |
| 帧率 | 24000/1001、24、25、30000/1001、30 等 | 23.976 与 24、29.97 与 30 不能混作同一数值 |
| 帧率模式 | CFR 或 VFR | VFR 素材进入部分剪辑环境后可能产生音画漂移 |
| 扫描方式 | 逐行、隔行、胶片转电视信号 | 错误反交错或反胶转会造成梳齿、重复帧和节奏异常 |
| 色彩元数据 | 色彩原色、传递特性、矩阵、范围 | 标记错误会造成偏色、灰黑、死黑或高光异常 |
| 音频 | 编码、采样率、位深、声道布局 | 错误解释声道或重复重采样会影响最终声音 |

扩展名只说明容器，不能代替上述检查。相同的 `.mp4` 文件可能包含不同编码、位深、帧率模式和色彩信息。

## 二、必须区分的基础概念

### 容器、编码与像素格式

- **容器**负责组织视频、音频、字幕、章节和附件；
- **编码**决定数据如何压缩和解码；
- **像素格式**决定亮度、色度、位深等画面信息如何存储。

更换容器属于重封装（remux），通常不重新压缩；改变编码属于转码（transcode），需要重新解码和编码。

### 色彩原色、传递特性、矩阵与范围

这四项共同决定数字信号如何还原为可见图像。SD 内容常见 Rec.601，HD SDR 常见 Rec.709，UHD、HDR 或特殊制作流程可能使用 Rec.2020、PQ 或 HLG。分辨率只能作为线索，仍应结合来源与元数据核验。

有限范围与全范围解释错误时，画面可能发灰、压黑或高光截断。仅修改标签而不理解像素实际范围，同样可能制造新的错误。

### 色度采样与位深

- 4:4:4 保留完整色度采样，适合图形、文字和合成中间文件；
- 4:2:2 常用于制作与采集流程；
- 4:2:0 常用于发行和网络交付。

10-bit 并不自动提高已有 8-bit 素材的真实细节，但在调色、渐变、合成与多次处理过程中通常能减少量化误差。最终交付仍需服从播放环境和平台支持范围。

## 三、标准处理流程

### 1. 拆分与重封装

需要单独处理音轨、字幕或章节时，可使用 MKVToolNix 或 FFmpeg 拆分。只改变容器的重封装不会修复源编码问题。无重编码裁切通常还受关键帧位置限制，不能保证任意帧精确切割。

### 2. 解码与预处理

预处理只针对已经确认的问题，例如：

- 反交错或反胶转；
- 统一可变帧率素材；
- 修正已核实的色彩范围或矩阵解释；
- 在有依据时处理色带、锯齿、振铃、压缩块或噪声；
- 为剪辑软件生成代理或中间文件。

原始胶片颗粒、动画制作纹理和用于抑制色带的保护性噪声不应被默认视为瑕疵。降噪、锐化、去色带和补帧均可能改变作品原有画面，应按镜头检查。

### 3. 中间文件与代理

编辑中间文件以稳定解码、帧精确和保留处理余量为优先，常见选择包括 ProRes、DNxHR、CineForm 或图像序列。代理可以降低分辨率和码率，但必须能够可靠回连原文件。

高压缩 H.264、HEVC 和 AV1 更适合分发，不宜在可以避免时作为多代合成的中间格式。关键合成还可保存高位深图像序列或带透明通道的中间文件。

### 4. 编码

交付编码需要同时考虑画质、体积、编码时间和播放兼容：

| 使用场景 | 常见方向 | 说明 |
| --- | --- | --- |
| 编辑中间文件 | ProRes、DNxHR、CineForm、图像序列 | 优先稳定解码、帧精确和较低代际损失 |
| 归档母版 | 高质量中间编码或无损编码 | 同时保存音频、字幕、说明和校验值 |
| 通用网络交付 | H.264 | 兼容范围较广，具体档次与级别按平台要求 |
| 高效率交付 | HEVC、AV1 | 可提高压缩效率，但编码成本与设备兼容性需单独测试 |

CRF 表示质量目标，不是固定码率；同一 CRF 在不同片源、预设和编码器上的体积与结果均会变化。可靠做法是选取暗部渐变、快速运动、细线、粒子、颗粒和复杂合成等代表性片段进行短编码测试。

VBV、码率上限、分辨率、帧率和音频规格应依据目标平台或设备设置。没有平台约束时，不应为了套用旧教程而加入任意上限。

### 5. 封装

编码后的轨道需按交付目标封装为 MP4、MKV、MOV 等容器，并核对：

- 默认音轨、声道布局和语言标签；
- 字幕类型、字体附件和默认开关；
- 时间码、章节、标题与轨道名称；
- 色彩与 HDR 元数据；
- 平台是否接受该容器和编码组合。

### 6. 质量检查

质量检查至少包括：

1. 总时长、起始帧和结束帧；
2. 音画同步、长时间播放是否漂移；
3. 分辨率、实际帧率、CFR／VFR 与扫描方式；
4. 色彩原色、传递特性、矩阵和范围标记；
5. 暗部渐变、闪光、细线、快速运动、粒子和高纹理镜头；
6. 是否出现色带、锯齿、振铃、蚊噪、压缩块、重影或补帧扭曲；
7. 音频峰值、响度、声道、爆音和首尾静音；
8. 在目标播放器和平台转码后再次抽查；
9. 母版、发布版与工程版本对应关系及 SHA-256 校验值。

只检查文件能否打开不足以证明交付合格。检查应覆盖首尾、随机片段以及最容易暴露问题的代表性镜头。

## 四、帧率与动画素材

动画源可能同时包含 24p、30p、30i、24t、24d、重复帧或混合模式。处理原则如下：

- 保留真实运动节奏，不把所有素材默认转换为 60 fps；
- 区分 `24000/1001` 与整数 `24`；
- 隔行源先判断属于摄像隔行、胶片转制还是混合编辑，再选择反交错或反胶转；
- VFR 网络视频或手机素材进入 CFR 时间线前，需要检查时间戳和音画同步；
- 光流补帧属于画面重建，不是无损帧率转换，遮挡和切镜处必须逐帧复核。

## 五、常见画面问题

| 问题 | 画面表现 | 处理原则 |
| --- | --- | --- |
| Banding／色带 | 渐变区域出现明显色阶 | 先确认位深、压缩与色彩处理链，再决定去色带和抖动 |
| Aliasing／锯齿 | 斜线、细线或缩放边缘呈台阶 | 检查缩放算法、源分辨率和处理顺序 |
| Ringing／Haloing | 线条周围出现亮边、暗边或振铃 | 避免叠加过度锐化，仅修复明确存在的问题 |
| Noise／Grain | 随机纹理或胶片颗粒 | 区分制作纹理、保护性噪声与真正干扰 |
| Blocking | 低码率区域出现方块 | 回到更高质量来源；后处理只能缓解，不能恢复真实细节 |
| Mosquito Noise | 线条或文字周围出现游动噪点 | 常与有损压缩有关，应优先改善源与编码条件 |
